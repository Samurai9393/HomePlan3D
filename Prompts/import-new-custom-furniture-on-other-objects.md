# Prompt: Import new custom furniture on other objects

## Goal

Update the project so new custom furniture can be imported and placed on other objects.

## Important: resolve scope first

The phrase "on other objects" is ambiguous in this repository and there is no persisted parent/child attachment model today. Before changing code, ask the user **one** clarifying question to determine which meaning applies:

- Furniture placed on top of other furniture surfaces (`mount: "surface"` / `surface: true`, geometric `surfaceHeight()` lookup)
- Furniture mounted on walls (`mount: "wall"`, wall item logic)
- Furniture inside blocks/groups (`group`)
- Furniture attached to rooms, openings, outdoor objects, or another `Floor` object
- A new explicit object-attachment model stored with each furniture item

Do not assume an answer. If the user picks a new attachment model, call out that this is a data-model change requiring frontend + backend schema + persistence updates.

## Verified context (working tree, 2026-11-22)

- Custom furniture = signed furniture packs (`.fp3dpack`); there is no `customFurniture` type/field.
- Pack type format: `pack:<pack id>:<item id>` (`frontend/src/packs.ts:175-177`).
- Pack schema: `custom_components/neonplan3d/packs.py:122-181`; TypeScript mirror: `frontend/src/packs.ts:103-133`.
- Pack docs: `docs/packs.md`; signing tool: `tools/fp3dpack.py`.
- Existing pack import path works: editor/extensions UI → `importPack()` (`frontend/src/api.ts:309-316`) → websocket `neonplan3d/packs/import` (`custom_components/neonplan3d/websocket.py:474-503`) → `verify_pack()` → `setPacks()` (`frontend/src/building-controller.ts:318-337`).
- Complete NeonPlan plan import already preserves `pack:` furniture types (`frontend/src/import/simple.ts:140-149`).
- Simple import format drops `pack:` types because `RawFurniture.type` is restricted to built-ins (`frontend/src/import/builder.ts:36-49`, `:127`; parser at `frontend/src/import/simple.ts:31`, `:71-77`).
- "On surfaces" today is geometric: x/z overlap plus `surfaceHeight()` (`frontend/src/model.ts:1758-1771`), plus `mountBase()` (`frontend/src/packs.ts:351-380`) and explicit `mount_y`. No object id is stored.
- Importer elevation path: `frontend/src/import/builder.ts:357-399` (`y > 0.05` becomes `mount_y`).
- Wall logic: `frontend/src/geometry/wall-frame.ts:49-101`; block/group field: `frontend/src/model.ts:198-199` and `custom_components/neonplan3d/schema.py:411-412`.
- Backend already accepts arbitrary furniture type strings up to 96 chars (`custom_components/neonplan3d/schema.py:254-258`) and `mount_y` in `-5..10` (`:308-310`).
- Build outputs under `custom_components/neonplan3d/frontend/` and `site/import/` are generated by `frontend/build.mjs`; never hand-edit them.

## Constraints

## Definition of done

- The chosen meaning is confirmed by the user before implementation.
- New custom furniture imports with its pack type intact and appears correctly on the intended target object.
- Round-trip through save/export/import and backup preserves the placement.
- Existing packs and built-in furniture behavior are unchanged.
- Tests added/updated for the changed import and placement logic.
- Verification run from `frontend/`: `npm test`, `npm run typecheck`, `npm run build`; from repo root: `pytest`.
