# STL to fp3dpack converter tool

## 2026-11-24 — Step 2 foundation built on branch `tool/stl-to-fp3dpack-guided`
- What: Plan `Plans/stl-to-fp3dpack-guided-converter.md` drives a standalone WinForms C# tool in `tools/StlToFp3dPack/` (net8.0-windows, OpenTK.GLControl 4.0.2). Branch `tool/stl-to-fp3dpack-guided` was created from `main` and left unmerged. Steps 1–7 are checked off.
- What: The step-2 code splits into `Models/PackModels.cs` (strongly typed fp3dpack v1 document, nullable optional fields), `Io/StlReader.cs` (ASCII/binary STL), `Io/MeshNormalizer.cs` (explicit up-axis, uniform scaling from one target longest extent, bounding-box seed part), `Io/PackValidator.cs` (mirrors `packs.py` field limits), `Io/PackDocumentIo.cs` (envelope-aware read, legacy-field stripping, Save As/overwrite), `Services/PackEditor.cs` (metadata, add/remove item with rollback) and `Services/StlImportSession.cs` (one STL conversion in progress). `UI/MainForm.cs` is the shell.
- What: Step 3 added `Rendering/PreviewScene.cs`, `Rendering/PreviewColors.cs` and `Rendering/Picking.cs` as pure scene/color/ray-picking logic, plus `UI/ModelViewport.cs` as the OpenTK.GLControl 4.x host. The viewport draws the scaled STL as a blue wireframe, shaded box/cylinder parts with axis/rot, a yellow selection outline and a ground grid, with drag orbit, wheel zoom, Reset view and Fit model. `ContextProfile.Compatability` (OpenTK's misspelling) enables the fixed-function pipeline. `glass` maps to a light cyan preview with alpha 0.72; the UI states it is a color-role approximation with no exported opacity.
- What: Step 4 completed the primitive-part editor: Add box/cyl, duplicate, delete, Move up/down, visible `Parts: n / 60` count, fields for `shape`, `x`, `z`, `w`, `d`, `y`, `h`, `axis`, `rot` and `color`, a `ColorDialog` picker for `#rrggbb`, all 12 allowed palette roles in a dropdown, and a Glass-like look toggle that exports only `color: "glass"`. The toggle and preview both warn that `fp3dpack` cannot store real transparency. The bounding-box seed uses `x/z/y/w/d/h = 0/0/0/1/1/1` and `body` after the target size is applied. `StlImportSession.MovePart()` handles reordering and Add/Duplicate enforce the 60-part cap.
- What: Step 5 added `tools/StlToFp3dPack.Tests/` as a net8.0-windows xUnit project referencing the WinForms app. It covers ASCII/binary STL parsing and count validation, up-axis and uniform scaling, target/derived-size rejection, bounding-box seeding, all palette roles and hex colors, glass export without opacity/alpha/transparency fields, valid/envelope pack reads, character-limit rejection, JSON shape, pack add/duplicate-id/remove/metadata operations, and validator failures. Tests generate STL/pack data in memory or in unique OS temp folders; no sample data is tracked. `dotnet test tools/StlToFp3dPack.Tests/StlToFp3dPack.Tests.csproj -c Release` passed 55/55.
- What: Step 6 added `tools/StlToFp3dPack/README.md` with build/run/test commands, pack create/open and metadata workflow, explicit up-axis and target-longest-extent import, part/color/glass editing, viewport controls, item add/remove rules, and Save As/overwrite behavior. It states that `fp3dpack` v1 has no real transparency, opacity, alpha, textures or UVs.
- What: Step 7 audit found no `.stl` or `.fp3dpack` files anywhere in the repository and no JSON under `tools/StlToFp3dPack/`. Test fixtures are synthetic strings generated at runtime in unique OS temp folders. The pre-existing untracked `Plans/fp3dpack-v1-*.json` template/example files were left untouched. No IP addresses were found in the tool source.
- What: Schema caveat found while implementing: `items` can be empty, but `validate_payload()` rejects a pack with no items, no features and no module. The tool rolls back removal of the last item unless features or module exist. The plan was corrected to say this.
- What: Build command `dotnet build tools/StlToFp3dPack/StlToFp3dPack.csproj -c Release` was green with 0 warnings. A throwaway harness outside the repo confirmed uniform scaling, JSON round-trip, envelope read, duplicate-free item add, empty-pack rejection, preview scene construction, glass preview alpha, ray picking, part reordering, glass/axis/rotation export and the 60-part cap without creating an OpenGL context. `tools/StlToFp3dPack/bin/` and `obj/` were added to `.gitignore`.
- Why: Later steps must not reintroduce silent auto-scaling, unit guessing, opacity fields or textures; the pack format has no such fields. Preserve the branch and keep build artifacts out of git.

## 2026-11-24 — Selecting a pack item loads it for in-place editing
- What: `Plans/load-selected-item-for-editing.md` drove a change to `UI/MainForm.cs`: selecting an item in **Pack items** loads id, name, size, group, room, tags, mount, light, wall y, flags, parts and preview into a new **Selected item** panel. `Apply to item` writes those fields back to the selected pack item; part edits and preview now use that item's parts and size instead of always using `StlImportSession`.
- What: `PackEditor.UpdateItem(string, PackItemEdit)` replaces only exposed fields, rejects duplicate ids, validates the full pack and rolls back on failure. `PackItem`, `PackPart`, `PackSymbol`, `PackSlot` and `PartBind` gained `Clone()` helpers so unexposed fields (`symbol`, `family`, `variant`, `slots`, loft fields, glow, binds) survive edits.
- What: `PreviewScene.Create` accepts an optional explicit size so a loaded item can be previewed without an STL mesh; `loft` is selectable in the part shape dropdown. Opening an STL or applying size switches back to import mode; adding an item appends and then selects the new item; removing an item selects an adjacent one.
- What: `README.md` documents the selected-item workflow. `dotnet build tools/StlToFp3dPack/StlToFp3dPack.csproj -c Release` stayed green with 0 warnings; `dotnet test tools/StlToFp3dPack.Tests/StlToFp3dPack.Tests.csproj -c Release` passed 61/61 after adding update, rollback, duplicate-id, save/reopen and explicit-size preview tests.
- Why: Loaded packs must be editable without recreating items from STL; unexposed `fp3dpack` fields must not be silently dropped.
