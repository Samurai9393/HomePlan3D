# STL to fp3dpack converter tool

## 2026-11-24 — Guided converter built on branch `tool/stl-to-fp3dpack-guided`
- What: `Plans/stl-to-fp3dpack-guided-converter.md` drove all seven steps; every step is checked off. Branch `tool/stl-to-fp3dpack-guided` was created from `main` and left unmerged for the user. The tool is standalone WinForms at `tools/StlToFp3dPack/` (`net8.0-windows`, OpenTK.GLControl 4.0.2) and does not change HomePlan runtime files.
- What: Code splits into `Models/PackModels.cs` (typed unsigned `fp3dpack` v1 document), `Io/StlReader.cs` (ASCII/binary STL), `Io/MeshNormalizer.cs` (explicit Y-up/Z-up, uniform scaling from one target longest extent, bounding-box seed part), `Io/PackValidator.cs` (mirrors `packs.py` limits), `Io/PackDocumentIo.cs` (envelope-aware read, legacy-field stripping, Save As/overwrite), `Services/PackEditor.cs` (metadata, add/remove item with rollback), `Services/StlImportSession.cs` (one STL conversion), `Rendering/` (OpenGL-independent scene/color/picking), `UI/ModelViewport.cs` (OpenTK host) and `UI/MainForm.cs`. `tools/StlToFp3dPack/README.md` documents build, run and workflow.
- What: Workflow requires an explicit up-axis and target longest extent in `0.01..10` metres; scaling is uniform and derived dimensions outside `0.01..10` are rejected. One STL becomes one appended pack item. Parts support `box`/`cyl`, a 60-part cap, reordering, palette roles or `#rrggbb`, and a Glass-like look that exports only `color: "glass"`. `fp3dpack` v1 has no real transparency, opacity, alpha, textures or UVs.
- What: `tools/StlToFp3dPack.Tests/` is a net8.0-windows xUnit project with 55 passing tests covering STL parsing, normalization, size rejection, colors, glass export with no opacity fields, pack read/write/validation, item operations and metadata edits. Fixtures are synthetic strings generated in unique OS temp folders. `dotnet build tools/StlToFp3dPack/StlToFp3dPack.csproj -c Release` and `dotnet test tools/StlToFp3dPack.Tests/StlToFp3dPack.Tests.csproj -c Release` were green.
- What: Schema caveat: `items` can be empty only if the pack has at least one feature or module; removing the last item otherwise rolls back. Step 7 audit found no `.stl` or `.fp3dpack` files and no JSON under `tools/StlToFp3dPack/`; pre-existing untracked `Plans/fp3dpack-v1-*.json` template/example files were left untouched.
- Why: Preserve the unmerged branch for user review and do not reintroduce silent auto-scaling, unit guessing, opacity fields or textures. Keep build artifacts out of git.
