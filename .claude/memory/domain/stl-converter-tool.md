- What: `Plans/stl-to-fp3dpack-guided-converter.md` drove all seven steps; every step is checked off. Branch `tool/stl-to-fp3dpack-guided` was created from `main` and left unmerged for the user. - What: Code splits into `Models/PackModels.cs` (strongly typed unsigned `fp3dpack` v1 document, nullable optional fields), `Io/StlReader.cs` (ASCII/binary STL), `Io/MeshNormalizer.cs` (explicit Y-up/Z-up, uniform scaling from one target longest extent, bounding-box seed part), `Io/PackValidator.cs` (mirrors `packs.py` field limits), `Io/PackDocumentIo.cs` (envelope-aware read, legacy-field stripping, Save As/overwrite), `Services/PackEditor.cs` (metadata, add/remove item with rollback), `Services/StlImportSession.cs` (one STL conversion), `Rendering/` (pure scene/color/ray-picking logic), `UI/ModelViewport.cs` (OpenTK host) and `UI/MainForm.cs`. `tools/StlToFp3dPack/README.md` documents build, run and workflow.
- What: Step 3 added a preview that draws the scaled STL as a blue wireframe, shaded box/cylinder parts with axis/rot, a yellow selection outline and a ground grid, with drag orbit, wheel zoom, Reset view and Fit model. `ContextProfile.Compatability` (OpenTK's misspelling) enables the fixed-function pipeline. `glass` maps to a light cyan preview with alpha `0.72` only; export stays `color: "glass"`.
- What: Step 4 completed the primitive-part editor: Add box/cyl, duplicate, delete, Move up/down, visible `Parts: n / 60` count, fields for `shape`, `x`, `z`, `w`, `d`, `y`, `h`, `axis`, `rot` and `color`, a `ColorDialog` picker for `#rrggbb`, all 12 allowed palette roles, and a Glass-like look toggle with a warning that `fp3dpack` v1 has no real transparency. The bounding-box seed uses `x/z/y/w/d/h = 0/0/0/1/1/1` and `body` after target size is applied. Add/Duplicate enforce the 60-part cap.
- What: Workflow requires an explicit up-axis and one target longest extent in `0.01..10` metres. Scaling is uniform, derived dimensions outside `0.01..10` are rejected, and there is no unit guessing. One STL becomes one appended pack item. Parts support `box`/`cyl`, reordering, palette roles or `#rrggbb`, and glass only as a palette role.
- What: Step 5 added `tools/StlToFp3dPack.Tests/` as a net8.0-windows xUnit project referencing the WinForms app. It covers ASCII/binary STL parsing and count validation, up-axis and uniform scaling, target/derived-size rejection, bounding-box seeding, all palette roles and hex colors, glass export without opacity/alpha/transparency fields, valid/envelope pack reads, character-limit rejection, JSON shape, pack add/duplicate-id/remove/metadata operations, and validator failures. Tests generate STL/pack data in memory or in unique OS temp folders; no sample data is tracked. `dotnet test tools/StlToFp3dPack.Tests/StlToFp3dPack.Tests.csproj -c Release` passed 55/55.

## 2026-11-24 — Selecting a pack item loads it for in-place editing
- What: `Plans/load-selected-item-for-editing.md` drove a change to `UI/MainForm.cs`: selecting an item in **Pack items** loads id, name, size, group, room, tags, mount, light, wall y, flags, parts and preview into a new **Selected item** panel. `Apply to item` writes those fields back to the selected pack item; part edits and preview now use that item's parts and size instead of always using `StlImportSession`.
- What: `PackEditor.UpdateItem(string, PackItemEdit)` replaces only exposed fields, rejects duplicate ids, validates the full pack and rolls back on failure. `PackItem`, `PackPart`, `PackSymbol`, `PackSlot` and `PartBind` gained `Clone()` helpers so unexposed fields (`symbol`, `family`, `variant`, `slots`, loft fields, glow, binds) survive edits.
- What: `PreviewScene.Create` accepts an optional explicit size so a loaded item can be previewed without an STL mesh; `loft` is selectable in the part shape dropdown. Opening an STL or applying size switches back to import mode; adding an item appends and then selects the new item; removing an item selects an adjacent one.
- What: `README.md` documents the selected-item workflow. `dotnet build tools/StlToFp3dPack/StlToFp3dPack.csproj -c Release` stayed green with 0 warnings; `dotnet test tools/StlToFp3dPack.Tests/StlToFp3dPack.Tests.csproj -c Release` passed 61/61 after adding update, rollback, duplicate-id, save/reopen and explicit-size preview tests.
- Why: Loaded packs must be editable without recreating items from STL; unexposed `fp3dpack` fields must not be silently dropped.
