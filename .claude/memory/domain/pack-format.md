# Pack format

## 2026-11-23 — Furniture packs are local unsigned JSON
- What: The format is `fp3dpack`, version 1, imported as plain local JSON without signature or server. Authoritative schema: `custom_components/homeplan3d/packs.py`; human-readable spec: `docs/packs.md`. Top level: `format`, `version`, `id`, `name`, `publisher`, optional `description`, `features`, `module`, `items`. `items[].size` is `[width, depth, height]` in metres; `parts` are `box`, `cyl` or `loft` with `x`/`z`/`w`/`d`/`y`/`h` as fractions of the item size.
- Why: User asked directly; records the canonical source locations and core shape without re-reading code.

## 2026-11-23 — Current `fp3dpack` v1 field shapes
- What: Authoritative validation is `custom_components/homeplan3d/packs.py`: `PAYLOAD_SCHEMA` (:211-230), `ITEM_SCHEMA` (:115-176), `PART_SCHEMA` (:48-97), `SYMBOL_SCHEMA` (:100-113). Top level requires `format: "fp3dpack"`, `version: 1`, `id`, `name`, `publisher`, `items`; optional `release`, `description`, `features`, `module`. An item requires `id`, `name` as a language map such as `{"en": "..."}` (language key 2-5 chars), `size` as exactly 3 metre values, and 1-60 `parts`; optional fields include `electric`, `mount`, `wall_y`, `surface`, `vehicle`, `hole`, `light`, `symbol`, `group`, `room`, `tags`, `family`, `variant`, `slots`. Part colors are `#rrggbb` or palette roles; parts support `box`, `cyl`, `loft`, `fix`, `rot`, `axis`, `top`, `edges`, `glow`, `screen`, `finish`, loft top fields and live-part `bind`. Symbols are `rect`, `circle` or `line`.
- Why: The `docs/packs.md:20-38` example is stale because it uses `"name": "Retro fridge"` instead of the required language map; future templates and examples must follow the schema above and be validated with `packs.read_pack()` before use.
