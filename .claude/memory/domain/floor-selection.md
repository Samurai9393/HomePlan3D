# Floor selection rendering

## 2026-11-24 — One `floorId` drives both 2D filtering and 3D visibility
- What: A selected floor is one id: `null` means the whole house, a string id means one floor. The 2D editor holds it as `_floorId` (`frontend/src/components/editor.ts:544`), resolves the floor at `:1414`, filters the plan to that floor's rooms/walls/furniture/outdoor areas in `render()` at `:6180`, and draws the floor below faintly as a ghost at `:6451`. The floor menu at `:5735-5752` lists floors highest-first and marks the active one with `fp3d-menu-on` and a check mark; `selectFloor()` at `:5723` clears room/vertex/draft state and refits the plan.
- What: `homeplan3d-view3d` receives `floorId` (`frontend/src/components/view3d.ts:278`) and calls `viewer.setFloor()` on changes (`:1233`). Floor pins, room taps, device navigation and voice navigation emit `floor-tap` or `room-tap` events back to the parent (`:1067`, `:1923-1926`). In whole-house view the viewer shows floor name/info pins; in a selected floor it shows room pins (`frontend/src/viewer/viewer3d.ts:3342-3364`).
- What: The 3D viewer positions each floor group at its elevation and controls selection with `setFloor()` (`viewer3d.ts:992-1004`), `applyTargets()` (`:3695-3726`) and `applyFloor()` (`:3731-3773`). Selected floors stay opaque at normal height; floors above move up by `5 + rank` and fade to zero; floors below are dimmed to `BELOW_OPACITY` (`0.22`), stacked at normal height, or hidden according to `floorStack` (`dim`, `stacked`, `single`). `stepFloors()` animates height and opacity. Room selection tints floor triangles with `ACTIVE_FLOOR` and activates its pin (`:4855-4874`).
- What: The side floor switcher is a thumbnail rail, not a plain list (`view3d.ts:4056-4111`). `floorThumbnails()` renders each floor alone offscreen with an orthographic camera, cut walls and no roof/ghost (`viewer3d.ts:5450-5504`). Buttons are sorted highest floor first; the active one uses `aria-pressed="true"`, styled with an accent border and glow (`view3d.ts:7225-7232`). The editor normally passes `floorStack: "single"` (`editor.ts:1316`), while panel/card views allow `dim`, `stacked` or `single`.
- Why: Future changes to floor switching, thumbnails, or multi-floor visibility need to update both the editor's 2D filtering and the viewer's group/material target logic; changing only the selector UI leaves the other view inconsistent.
